Изучены исходники на указанных коммитах (неглубокие клоны) и копии модов из бэкапа книги.
Лицензия определяет, что из проекта можно брать: **код** из GPL/AGPL-проектов переносится только
в проект с совместимой лицензией, **факты** (номера ioctl, коды кнопок, пути sysfs) — в любой.
Выбор лицензии проекта — открытый вопрос в [требованиях](../decisions/Требования%20к%20продукту%20v1.md#открытые-вопросы).

## Что берём из каждого

### inkshelf — образец устройства проекта

Ближайший по стеку проект: доказывает, что e-ink-приложение на чистом Go без cgo работает.

- Сборка одной командой `CGO_ENABLED=0 GOOS=linux GOARCH=arm GOARM=7` —
  [`Makefile`](https://github.com/CedricHerzog/inkshelf/blob/18723c25fe8f8fbbdac172b36969835037daac9b/Makefile).
- Код устройства — в файлах `_linux_arm.go`, на хосте вместо них эмулированная прошивка;
  `go test ./...` идёт на ноутбуке.
- Эмулятор в браузере, скрипты «тап / кнопка / пауза / снимок», эталонные снимки и их сравнение —
  [`docs/reference/emulator.md`](https://github.com/CedricHerzog/inkshelf/blob/18723c25fe8f8fbbdac172b36969835037daac9b/docs/reference/emulator.md).
- Слои пакетов снизу вверх и правило импорта, проверяемое `go list -deps` —
  [`docs/reference/architecture.md`](https://github.com/CedricHerzog/inkshelf/blob/18723c25fe8f8fbbdac172b36969835037daac9b/docs/reference/architecture.md).
- Учёт перекрывающихся обновлений экрана: ждать только те, что пересекаются с новым прямоугольником —
  [`docs/reference/eink-and-firmware.md`](https://github.com/CedricHerzog/inkshelf/blob/18723c25fe8f8fbbdac172b36969835037daac9b/docs/reference/eink-and-firmware.md).
- Удалённое управление по Wi-Fi: деплой, логи, снимки, профилирование (`cmd/readerctl`).

Отличие Kobo от PocketBook: на PocketBook ввод и экран идут через процесс прошивки, на Kobo
приложение после остановки Nickel само читает `/dev/input` и шлёт ioctl во фреймбуфер.

### Plato — образец жизненного цикла на Kobo

- Остановка Nickel, перехват экрана, возврат в Nickel —
  `backup/.adds/plato/plato.sh` и `backup/.adds/plato/nickel.sh` (копии с книги).
- Сон, Wi-Fi, USB mass storage без Nickel — скрипты `backup/.adds/plato/scripts/`.
- Повороты и зеркалирование тача по моделям —
  [`crates/core/src/device.rs` → `mirroring_scheme()`](https://github.com/baskerville/plato/blob/7da89f296e58c7426692abb6fda16431b9631e60/crates/core/src/device.rs).
- Обновление экрана на Mark 7 —
  [`crates/core/src/framebuffer/kobo2.rs` → `update()`](https://github.com/baskerville/plato/blob/7da89f296e58c7426692abb6fda16431b9631e60/crates/core/src/framebuffer/kobo2.rs).
- События USB из FIFO udev —
  [`crates/core/src/input.rs` → `parse_usb_events()`](https://github.com/baskerville/plato/blob/7da89f296e58c7426692abb6fda16431b9631e60/crates/core/src/input.rs).
- Плагины-«хуки»: внешняя программа, обмен JSON через stdin/stdout (`article_fetcher` в
  `backup/.adds/plato/Settings.toml`) — образец для внешних приложений.

### KOReader — база квирков

- Описание Forma —
  [`frontend/device/kobo/device.lua` → `KoboFrost`](https://github.com/koreader/koreader/blob/v2025.04/frontend/device/kobo/device.lua).
- Запуск и возврат в Nickel, губернатор CPU, Wi-Fi —

### FBInk — эталон ioctl

Не подключаем как библиотеку ([ADR-0002](../adr/ADR-0002%20Чистый%20Go%20без%20cgo.md)), но сверяем с ним всё,
что касается экрана: структуры и номера ioctl
([`eink/mxcfb-kobo.h`](https://github.com/NiLuJe/FBInk/blob/886f25f13368859ad8a899b88d04c26e19cda32e/eink/mxcfb-kobo.h)),
квирки модели
([`fbink_device_id.c` → `DEVICE_KOBO_FORMA`](https://github.com/NiLuJe/FBInk/blob/886f25f13368859ad8a899b88d04c26e19cda32e/fbink_device_id.c)),
порядок флагов на Mark 7
([`fbink.c` → `refresh_kobo_mk7()`](https://github.com/NiLuJe/FBInk/blob/886f25f13368859ad8a899b88d04c26e19cda32e/fbink.c)).
CLI `fbink` уже лежит на книге в папке KOReader — годится для диагностики.

### rmkit и vlasovsoft — образцы платформы

- rmkit: общая библиотека, вкомпилированная в каждое приложение, и лаунчер remux, который
  запускает приложения отдельными процессами и замораживает фоновые (`SIGSTOP`/`SIGCONT`) —
  [`src/remux/launcher.cpy`](https://github.com/rmkit-dev/rmkit/blob/fc372b29c6f19e4da645277e1902255e3198b59f/src/remux/launcher.cpy).
  Приложения регистрируются файлами-описаниями («draft»).
- vlasovsoft: лаунчер и приложения — отдельные Qt-бинарники; список в `applications.ini`
  (`имя = скрипт`), общий стиль `eink.qss` (`backup/.adds/vlasovsoft/`).

Как это повлияло на выбор архитектуры — [ADR-0001](../adr/ADR-0001%20Оболочка,%20SDK%20и%20встроенные%20приложения.md).

### NickelMenu, KFMon, NickelDBus — точки входа из Nickel

- NickelMenu: действие `cmd_spawn` запускает команду через `/bin/sh -c` в фоне; конфиг
  перечитывается при изменении файлов (сравнение mtime в
  [`src/config.c`](https://github.com/pgaskin/NickelMenu/blob/bc799ebe95a413a4857aa97a88e2b16557e6427f/src/config.c));
  удаление — файл `uninstall` в `.adds/nm/` или выключение книги сразу после старта загрузки.
  Прошивки 5.x не поддерживает.
- KFMon: PNG-файл в библиотеке как ярлык; при открытии запускается скрипт из `.adds/kfmon/config/*.ini`.
- NickelDBus: нужен, только если приложение работает **рядом** с Nickel (диалоги, тосты).
  В выбранной схеме ([ADR-0003](../adr/ADR-0003%20Запуск%20поверх%20Nickel%20через%20NickelMenu.md)) Nickel остановлен, и он не используется.

### gotd/td — основа будущего Telegram-клиента

Чистый Go, MIT, низкоуровневый MTProto; нужны собственные `api_id` и `api_hash` с my.telegram.org.
Версия `v0.162.0` требует Go 1.25 — совпадает с установленной у владельца.
