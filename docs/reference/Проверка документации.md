# Проверка документации

**Тип:** справочник · **Аудитория:** все, кто пишет документацию, ИИ-агенты · **Статус документа:** живой · **Актуально на:** 19.10.2026

**Когда читать:** проверка документации упала и надо понять, что она требует, — или решаете, какой пункт стандарта перевести из ревью в инструмент.

---

Инструмент — `tools/doccheck`, точка входа — `tools/doccheck/main.go` → `main()`. Как запускать —
в [«Настройке окружения разработки»](../guides/Настройка%20окружения%20разработки.md).
Требования, которые он проверяет, — в [стандарте](../rules/Стандарт%20документации.md).

## Откуда читаются файлы

Флаг `-src` выбирает состояние репозитория (§6 стандарта, отказ О-15):

| Значение | Что читается | Кто использует |
|---|---|---|
| `head` | последний коммит | `make check` по умолчанию |
| `index` | индекс git — то, что уйдёт в коммит | хук перед коммитом |
| `worktree` | рабочее дерево без игнорируемых файлов | до первого коммита и для черновиков |

Проверка всегда переходит в корень репозитория, в каком бы каталоге её ни запустили.

## Что проверяется

| Проверка | Требование | § стандарта | Где в коде |
|---|---|---|---|
| `шапка` | H1 совпадает с именем файла; поля шапки заполнены; статус из списка; дата `ДД.ММ.ГГГГ` («Снято» у снимка); у ADR, руководства и внешнего материала — свои поля; тип совпадает с каталогом | §3, §9 | `tools/doccheck/checks.go` → `checkHeader()` |
| `индекс` | каждый документ `docs/` упомянут ссылкой в `docs/README.md` | §9 | `tools/doccheck/checks.go` → `checkLinkedFrom()` |
| `инструкция` | `CLAUDE.md` есть в источнике и ссылается на каждое правило из `docs/rules/` | §3 | там же |
| `ссылка` | ссылка между документами ведёт в существующий файл и существующий заголовок | §11 | `tools/doccheck/checks.go` → `checkLinks()` |
| `adr-правило` | ADR не ссылается на правила | §1 | там же |
| `номер-строки` | нет формы `путь:номер` в тексте и `#L…` в ссылках | §5 | `tools/doccheck/checks.go` → `checkLineNumbers()` |
| `код` | ссылка «путь → якорь» ведёт в файл источника, и якорь в нём находится поиском | §5 | `tools/doccheck/checks.go` → `checkCodeRefs()` |
| `бюджет` | правило не длиннее 120 строк; исключения — в реестре долга | §8 | `tools/doccheck/checks.go` → `budgetExempt` |

Ссылки на чужой код оформляются ссылками наружу с коммитом в адресе; проверка их не открывает.
Содержимое огороженных блоков кода не проверяется.

## Что остаётся на ревью

Пункты §11, которые инструмент пока не ловит, — признанный риск:

- одна тема — одно место;
- числа в прозе — порядки, а не точные значения;
- факт снят с коммита, а не с рабочего дерева;
- сгенерированные блоки метрик (§4): блоков в репозитории ещё нет, генератора тоже.

Расхождения, оставленные сознательно, — в [реестре долга](Реестр%20долга.md).
