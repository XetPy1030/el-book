# ADR-0002 Чистый Go без cgo

**Тип:** ADR · **Аудитория:** разработчики платформы, ИИ-агенты · **Статус документа:** живой · **Актуально на:** 19.10.2026

**Статус решения:** принято как рабочее 19.10.2026, владелец может пересмотреть · **Действует в коде с:** 20.10.2026

**Когда читать:** хотите подключить C-библиотеку, cgo-пакет или собрать что-то тулчейном под ARM.

---

## Контекст

Код под книгу должен общаться с экраном (ioctl e-ink-контроллера, `mmap` фреймбуфера), вводом
(`evdev`), sysfs и сетью. Сторонние приложения на книге собраны под 32-битный ARM с динамическим
glibc прошивки ([снимок устройства](../reference/Устройство%20Kobo%20Forma%20—%20снимок%2019.10.2026.md#модель-и-прошивка)).
Разработка идёт на Mac с Apple Silicon, Go 1.25.

## Решение

Весь код — **чистый Go, сборка с `CGO_ENABLED=0`** под `GOOS=linux GOARCH=arm GOARM=7`.
Системные вызовы — через `golang.org/x/sys/unix`. Структуры и номера ioctl переносятся в Go
как факты из заголовков FBInk; FBInk, KOReader и Plato — эталон поведения, с которым сверяется
наша реализация ([обзор проектов](../reference/Существующие%20проекты%20—%20снимок%2019.10.2026.md)).

## Рассмотренные варианты

| Вариант | За | Против | Итог |
|---|---|---|---|
| **А. Чистый Go** | сборка одной командой на любой машине; статический бинарник не зависит от glibc прошивки; тесты и эмулятор на хосте без тулчейна; проверено: тестовый бинарник собирается статическим | квирки устройства реализуем сами; при поддержке многих моделей объём квирков растёт | **выбран** |
| **Б. cgo + FBInk** (через go-fbink-v2 или свою обёртку) | квирки десятков моделей уже решены | нужен кросс-тулчейн под старый glibc (koxtoolchain); go-fbink-v2 привязан к FBInk 1.23.0 и не обновлялся с 2021; лицензия GPL/AGPL обязательна | отвергнут |
| **В. Qt-приложение** (как UltimateMangaReader) | готовые виджеты, kobo-плагин платформы | не Go; Qt 5.15 занимает десятки мегабайт; тот же тулчейн | отвергнут |
| **Г. CLI `fbink` подпроцессом** | ноль своего кода экрана | запуск процесса на каждое обновление — слишком медленно для интерфейса | только для диагностики и спайков |

## Последствия

- Импорт `"C"` и cgo-зависимости в проекте не используются.
- Все зависимости — чистый Go; например, для Telegram — gotd/td, а не TDLib.
- Слой устройства Kobo сверяется с FBInk при каждом изменении кода обновления экрана.
- Перенос **кода** (а не фактов) из FBInk, KOReader, Plato или inkshelf возможен только при
  совместимой лицензии проекта — открытый вопрос в
  [требованиях](../decisions/Требования%20к%20продукту%20v1.md#открытые-вопросы).

## Когда пересмотреть

Платформа начинает поддерживать больше двух-трёх моделей Kobo разных поколений — тогда
сравнить стоимость своих квирков со стоимостью тулчейна и FBInk.
