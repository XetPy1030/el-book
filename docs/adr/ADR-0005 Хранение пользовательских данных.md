# ADR-0005 Хранение пользовательских данных

**Тип:** ADR · **Аудитория:** разработчики платформы и приложений, ИИ-агенты · **Статус документа:** живой · **Актуально на:** 19.10.2026

**Статус решения:** принято как рабочее 19.10.2026, владелец может пересмотреть · **Действует в коде с:** 20.10.2026

**Когда читать:** приложению нужно сохранить настройки, документы или кэш.

---

## Контекст

Сохранение пользовательских данных — обязательное требование постановки. Особенности книги:

- пользовательский раздел `/mnt/onboard` — FAT; нет прав доступа и ссылок, атомарность
  переименования при отключении питания не гарантирована;
- раздел переживает обновления прошивки и виден компьютеру по USB — им удобно делать бэкап;
- пока раздел отдан компьютеру по USB, писать на него нельзя;
- книга может выключиться в любой момент — севшая батарея, долгое нажатие питания.

## Решение

1. **Корень данных** — `/mnt/onboard/.adds/<имя проекта>/`:
   - `shell/` — настройки оболочки;
   - `apps/<id приложения>/settings.json` — настройки приложения;
   - `apps/<id приложения>/data/` — документы приложения (например, рисунки);
   - `apps/<id приложения>/cache/` — то, что можно удалить в любой момент;
   - `logs/` — журналы с ротацией.
2. **Запись только атомарная:** временный файл в той же папке → `fsync` → переименование поверх
   старого → `fsync` папки. Предыдущая версия настроек хранится рядом как `.bak`; если основной
   файл не читается, загружается она.
3. **Формат настроек — JSON с номером версии схемы**; миграции — функции «версия N → N+1».
4. **Приложение не видит путей**: SDK выдаёт ему хранилище с операциями «прочитать / записать
   настройки» и «папка документов». Писать мимо хранилища нельзя.
5. **Базы данных в первой версии нет.** Telegram-клиенту понадобится кэш сообщений — хранилище для
   него выбирается отдельным ADR на этапе Telegram.

## Рассмотренные варианты

| Вариант | За | Против | Итог |
|---|---|---|---|
| **А. JSON и файлы на `/mnt/onboard`, атомарная запись** | просто; бэкап копированием папки по USB; переживает прошивку | нет запросов и индексов | **выбран** для v1 |
| **Б. SQLite на чистом Go** (modernc) | запросы, транзакции | заметная прибавка к бинарнику и памяти; журнал SQLite на FAT при отключении питания — отдельный риск | отложен до Telegram |
| **В. bbolt** | простое KV, транзакции | `mmap` на FAT не проверен | отложен до Telegram |
| **Г. Системный раздел** (`/usr/local`) | не виден по USB | стирается обновлением прошивки; системный раздел исключён [ADR-0003](ADR-0003%20Запуск%20поверх%20Nickel%20через%20NickelMenu.md) | отвергнут |

## Последствия

- Бэкап и перенос данных владелец делает сам — копированием папки проекта по USB.
- Перед выходом в Nickel и перед сном оболочка сбрасывает все незаписанные данные.
- Потеря последнего штриха или последней правки при внезапном отключении питания допустима,
  повреждение файла — нет.
