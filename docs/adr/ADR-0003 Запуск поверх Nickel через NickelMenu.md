# ADR-0003 Запуск поверх Nickel через NickelMenu

**Тип:** ADR · **Аудитория:** владелец проекта, разработчики платформы, ИИ-агенты · **Статус документа:** живой · **Актуально на:** 19.10.2026

**Статус решения:** принято как рабочее 19.10.2026, владелец может пересмотреть · **Действует в коде с:** 20.10.2026

**Когда читать:** меняете способ запуска оболочки, скрипт запуска или возврат в Nickel.

---

## Контекст

На книге уже стоят NickelMenu и KFMon, через них запускаются KOReader, Plato, vlasovsoft и
UltimateMangaReader ([снимок устройства](../reference/Устройство%20Kobo%20Forma%20—%20снимок%2019.10.2026.md#установленные-моды)).
Механика передачи экрана от Nickel описана в
[«Жизненном цикле приложения»](../explanation/Жизненный%20цикл%20приложения%20на%20Kobo.md).
Владельцу нужен продукт, которым удобно пользоваться каждый день, и при этом нельзя
рисковать работоспособностью книги.

## Решение

1. **Точка входа — пункт NickelMenu** с действием `cmd_spawn`, вызывающий скрипт запуска
   через `sh` (права файлов на FAT-разделе задаёт монтирование, а не сам файл). Ярлык KFMon — необязательная вторая точка
   входа на тот же скрипт.
2. **Скрипт запуска** забирает окружение Nickel, останавливает Nickel по образцу KOReader,
   запускает оболочку и **при любом её завершении** — штатном, с ошибкой, по сигналу — возвращает Nickel.
3. **Загрузка книги не меняется:** ни `rcS`, ни системный раздел не трогаются, `KoboRoot.tgz`
   проект не выпускает.
4. Файлы проекта живут только в `/mnt/onboard/.adds/<имя проекта>/`; удалить проект — удалить
   эту папку и файл пункта NickelMenu.

## Рассмотренные варианты

| Вариант | За | Против | Итог |
|---|---|---|---|
| **А. NickelMenu → скрипт** | уже установлен; пункт меню доступен из любого экрана Nickel; конфиг — текстовый файл | после обновления прошивки NickelMenu, возможно, придётся переустановить | **выбран** |
| **Б. KFMon-ярлык** | иконка в библиотеке, «как книга» | ярлык виден как книга и путается с библиотекой | допускается вторым входом |
| **В. Загрузка сразу в оболочку** вместо Nickel | нет ожидания остановки Nickel | правка системного раздела; ошибка = книга не загружается; затирается обновлением прошивки; теряются магазин и синхронизация | отвергнут |
| **Г. Работать рядом с Nickel** | не нужно его останавливать | Nickel перерисовывает экран и читает ввод — два хозяина у одного устройства | отвергнут |

## Последствия

- Вход в оболочку стоит остановки Nickel, выход — его полной загрузки: несколько секунд.
  Поэтому оболочка должна быть местом, где удобно оставаться, а не тем, откуда выходят после каждого действия.
- Подключение к компьютеру по USB в первой версии — через выход в Nickel, который включит
  USB-накопитель сам ([требования](../decisions/Требования%20к%20продукту%20v1.md)).
- Аварийный выход для владельца: долгое нажатие кнопки питания перезагружает книгу в обычный Nickel;
  отключить NickelMenu — файл `uninstall` в `.adds/nm/`.
- Обновление прошивки до 5.x сломает NickelMenu — он её не поддерживает.

## Когда пересмотреть

Оболочка стала основным интерфейсом книги, а Nickel запускается редко, — тогда оценить
загрузку сразу в оболочку отдельным ADR, с планом восстановления.
