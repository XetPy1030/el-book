# Разработка в эмуляторе

**Тип:** руководство · **Аудитория:** разработчики платформы и приложений · **Статус документа:** живой · **Актуально на:** 20.10.2026

**Правила:** [«Правила кода»](../rules/Правила%20кода.md), [«Правила интерфейса»](../rules/Правила%20интерфейса.md)

**Когда читать:** меняете экран и хотите увидеть его без книги, пишете сценарий UI-теста или упал UI-тест.

---

Эмулятор запускает ту же оболочку с теми же приложениями, что и книга, но вместо Kobo — модель
книги в браузере ([ADR-0004](../adr/ADR-0004%20Эмулятор%20устройства%20в%20браузере.md)).

## 1. Запустить в браузере

```sh
make emu
```

Откройте <http://localhost:8740>. Мышь — палец: щелчок — касание, перетаскивание — ведение пальцем.
Кнопки под книгой — питание, обложка, кабель, заряд, поворот книги. С клавиатуры: стрелки
или PageUp/PageDown — кнопки листания, `p` — питание, `c` — обложка.

Панель меняется только тогда, когда приложение отправляет обновление, — как на e-ink.
Каждое обновление на миг подсвечивается рамкой, справа — журнал обновлений с режимами.
Двухцветные режимы (DU, A2) показывают картинку в два цвета: если серое пропало под
откликом на касание, на книге оно пропадёт так же.

Данные эмулированной книги лежат в `build/emu-data`. Другие параметры — `go run ./cmd/emulator -h`:
начать с пустыми данными, ждать обновлений столько, сколько на книге, начать в альбомной
ориентации, заморозить часы.

**Сеть.** Wi-Fi эмулятора — имитация: вокруг «книги» три сети (`sdk/device/emu/network.go` →
`knownAPs`), одна из них сохранена; пароль со словом `wrong` не подходит — так проверяется окно
неверного пароля. Сами запросы приложений идут через сеть компьютера. Галочка «Нет сети» под
книгой — Wi-Fi не находит знакомых сетей: так видно, как приложение живёт без интернета.

## 2. Написать сценарий

Сценарий — текстовый файл: по действию в строке. Команды перечислены в
`sdk/device/emu/script.go` → `RunScript()`: касание, долгое нажатие, свайп, ведение пальцем,
ведение с остановкой в конце (так выравниваются фигуры в рисовалке), кнопки, обложка, кабель,
заряд, поворот, сеть, снимок. Координаты — логические пиксели экрана 1440×1920 в портрете.
Заготовка:

```text
# Проверка нового экрана
tap 1240 1800          # «Настройки»
shot 01-settings
drag 200 900 1200 900  # провести пальцем
key pgback
shot 02-after-back
```

Прогнать сценарий без браузера и посмотреть снимки:

```sh
go run ./cmd/emulator -fresh -data build/try -clock 2026-10-19T14:05 -script мой.txt -out build/try-shots
```

Координаты кнопок удобно брать с такого снимка.

## 3. UI-тесты

Каждый сценарий из `emulator/scripts/` — UI-тест: его снимки сравниваются с эталонами
в `internal/uitest/testdata/<сценарий>/`. Тесты идут в `make check`; отдельно — `make uitest`.

Если тест упал, рядом с сообщением — путь в `build/uitest/<сценарий>/`: там фактический снимок
и картинка разницы, где несовпавшие пиксели чёрные.

- Изменение **нечаянное** — чините код.
- Изменение **задуманное** — посмотрите новые снимки глазами, перезапишите эталоны и закоммитьте
  их вместе с изменением интерфейса:

  ```sh
  make uitest-update
  ```

Новый сценарий: положите файл в `emulator/scripts/`, выполните `make uitest-update`, проверьте
появившиеся эталоны глазами.

Чтобы снимки не плыли от прогона к прогону:

- **Сеть — из файлов.** Приложения в UI-тестах не ходят в интернет: ответ берётся из
  `internal/uitest/testdata/http/` по таблице `routes.txt` — подстрока адреса и файл ответа.
  Запрос, которому ответа нет, роняет тест: допишите строку в таблицу и положите файл.
  Тексты в ответах выдуманы — чужие статьи в репозиторий не кладутся.
- **Часы и пояс заморожены**: 19.10.2026, 14:05 по Москве (`internal/uitest/uitest_test.go` → `zone`).
  Всё случайное в приложении берите от часов контекста (`ctx.Now()`), а не от глобального
  генератора — иначе картинка разная в каждом прогоне.
- **Тосты живут две с половиной секунды по настоящим часам.** Снимок с тостом — только сразу
  после действия, которое его показало; иначе перед снимком `wait 2700`.
- Сценарии идут параллельно, каждый — со своими данными: состояние одного не видно другому.

## 4. Снимки для глаз

`make shots` прогоняет дымовой сценарий и кладёт снимки в `build/shots`. Лист со всеми иконками
и начертаниями шрифта — `go run ./tools/sheet`, файл `build/sheet.png`.
